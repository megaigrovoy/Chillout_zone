# Chillout Zone

Интерактивное развлечение на React: MediaPipe отслеживает ладони через
веб-камеру, а на экране в реальном времени строятся **фрактальные пламёна**
(fractal flames) — те самые светящиеся спирали, которые рисуют в Apophysis.
Движение руки пересобирает фрактал.

Всё обрабатывается локально в браузере — видеопоток никуда не отправляется.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:5173 и разрешите доступ к камере.

Веб-камера требует защищённого контекста (secure context): `localhost` подходит,
а при открытии по IP в локальной сети нужен HTTPS.

## Управление

Трекинг идёт **только по ладони** — положение, поворот и раскрытость. Отдельные
пальцы не отслеживаются: их дрожание раньше расшатывало фигуру, а жест «поднять
руку» проще и надёжнее.

| Жест | Что происходит |
| --- | --- |
| Раскрыть ладонь | Спираль раскрывается шире, рукава расходятся |
| Сжать кулак | Тугая плотная спираль |
| Повернуть кисть | Вращение всей фигуры |
| Опустить руку | На ветвях появляется мелкое кружево (третье преобразование) |
| Двигать вбок | Смена палитры |
| Приблизить к камере | Фигура крупнее |

## Как это работает

Реализован **алгоритм фрактальных пламён** Скотта Дрейвза (2003) — тот самый,
на котором работают Apophysis, flam3 и JWildfire. Формулы вариаций взяты из
эталонной реализации [flam3](https://github.com/scottdraves/flam3)
(`variations.c`), а не придуманы.

Предыдущая версия рисовала спирали вручную и получала многоугольные завитушки:
чтобы форма выглядела фракталом, её надо не *рисовать*, а *итерировать*.

**Ничего не рисуется — всё накапливается.** Работает chaos game: точка миллионы
раз прогоняется через случайно выбираемые преобразования, и каждое попадание
складывается в гистограмму плотности. Изображение выводится из плотности.

Три новшества Дрейвза поверх классического IFS, и все три здесь существенны:

1. **Нелинейные вариации** (`variations.ts`) — 17 функций из flam3: `julia`,
   `spiral`, `disc`, `swirl`, `spherical`, `eyefish` и другие. Именно их
   смешивание даёт узнаваемую пластику пламён; одна вариация сама по себе
   почти всегда скучна.
2. **Логарифмическая тональная компрессия** — плотность охватывает несколько
   порядков, и при линейном отображении видно только яркое ядро. Формула
   `alpha = log(1 + count) / log(1 + max)`, затем `alpha^(1/gamma)`. Это и даёт
   мягкие светящиеся градиенты вместо плоских силуэтов.
3. **Структурное окрашивание** — цвет является координатой самой точки и
   смешивается с цветом преобразования на каждом шаге (`c = (c + c_xform)/2`).
   Поэтому оттенок кодирует *какие преобразования* сформировали область, а не
   красится сверху.

**Конструкция — «grand julian».** Вариация `julia` берёт квадратный корень с
случайным выбором ветви, что порождает самоподобное удвоение спиральных рукавов;
поверх накладываются `swirl` и `disc` для кружева на кромке и финальный
`eyefish` для характерной выпуклости.

**Рука пересобирает фрактал каждый кадр** — раскрытость меняет раскрыв спирали,
поворот вращает аффинные части, высота добавляет третье преобразование с мелкой
структурой, положение по горизонтали крутит палитру.

### Что показали замеры

Проверялось, что это действительно фрактал, а не шум: у пламени плотность
концентрируется в тонком множестве, поэтому её динамический диапазон велик.

| | Динамический диапазон | Занятость кадра |
| --- | --- | --- |
| Пламя (кулак) | 2.18 порядка | 65% |
| Пламя (раскрытая ладонь) | 1.66 порядка | 67% |
| Равномерный шум (контроль) | **0.36 порядка** | 100% |

Профилирование опровергло ожидание, что узкое место — chaos game. На деле он
занимал 3.8 мс, а **тональная компрессия — 22 мс**: `Math.log` и `Math.pow` на
каждый пиксель это ~2 млн трансцендентных вызовов в кадре. После замены `pow` на
таблицу и пакетного затухания кадр на 1920×1080 сократился с 31.3 до 16.6 мс.

| Стадия | 1280×720 | 1920×1080 |
| --- | --- | --- |
| Затухание | 0.39 мс | 0.93 мс |
| Chaos game | 3.04 мс | 3.51 мс |
| Тональная компрессия | 6.81 мс | 12.16 мс |
| **Итого** | **10.2 мс** | **16.6 мс** |

## Структура

```
src/
  tracking/
    types.ts             типы состояния руки
    handState.ts         сведение landmark'ов MediaPipe в сигнал ладони
    useHandTracking.ts   камера + цикл распознавания
  fractal/
    variations.ts        17 вариаций пламён из эталонного flam3
    flame.ts             chaos game, гистограмма, логарифмический tone mapping
    presets.ts           сборка «grand julian» по состоянию руки + палитра
    params.ts            маппинг рук в параметры + сглаживание
    render.ts            цикл накопления и вывод кадра
  components/
    FractalCanvas.tsx    цикл рендера на requestAnimationFrame
  App.tsx                экран запуска, HUD, отладочные данные
```

Решения, которые стоит знать при доработке:

- **Трекинг передаётся через ref, а не через state.** При 30–60 кадрах в секунду
  `setState` на каждый кадр перерисовывал бы всё дерево React и ронял бы FPS.
- **Параметры сглаживаются экспоненциально** с шагом от реального `dt`. Ощущение
  одинаковое на 30 и 144 Гц, а кратковременная потеря руки не даёт рывка.
- **`dt` ограничен сверху.** Вкладка, вернувшаяся из фона, иначе сделала бы один
  гигантский шаг.
- **Первые 20 точек каждого прогона отбрасываются** (fuse): начальная точка
  выбирается случайно и ещё не лежит на аттракторе, иначе по кадру рассыпались
  бы посторонние точки.
- **Ресайз пересоздаёт гистограмму** — плотность на пиксель зависит от
  разрешения, поэтому корректно масштабировать накопленное нельзя.
- **Холст рендерится в CSS-разрешении** (`dpr = 1`): `putImageData` игнорирует
  трансформации холста, а полный DPR-буфер учетверил бы работу tone mapping.
- **Handedness инвертируется** относительно MediaPipe: модель сообщает сторону с
  точки зрения камеры, а картинка зеркалится под зрителя.

Модель и WASM-рантайм MediaPipe загружаются с CDN при первом запуске — для старта
нужен интернет. Чтобы работало офлайн, положите `hand_landmarker.task` и wasm-файлы
в `public/` и поправьте `WASM_ROOT` и `MODEL_URL` в `useHandTracking.ts`.

## Настройка ощущения

- `render.ts` — `SAMPLES_PER_FRAME` (качество против скорости), `DECAY` (как
  долго живёт накопленное), `DECAY_INTERVAL`, параметры `toneMap` — гамма 2.2 и
  яркость 1.6, `camera.scale` (кадрирование)
- `presets.ts` — `grandJulian()`: веса вариаций, аффинные коэффициенты, число и
  цвет преобразований. Здесь же `buildPalette()` — косинусный градиент
- `variations.ts` — можно подмешивать любые из 17 вариаций или добавить свои по
  формулам из flam3
- `handState.ts` — `OPENNESS_MIN`/`OPENNESS_MAX` (калибровка раскрытости ладони)

Хотите другой узор — меняйте набор вариаций в `grandJulian()`. Это самый
действенный рычаг: пламя определяется в первую очередь тем, какие вариации
смешаны.
